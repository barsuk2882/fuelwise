# Прокси API заправок для FuelWise

## Зачем он нужен

`gde-benzin.ru/api/stations` отдаёт рабочий JSON, но ответ API не содержит `Access-Control-Allow-Origin`. Поэтому его можно открыть напрямую, однако браузерный JavaScript на GitHub Pages не вправе прочитать ответ. Worker добавляет разрешённые CORS-заголовки и передаёт запрос к источнику. Допустимая ширина запроса — до 1,5° по широте и 4° по долготе; больший масштаб отклоняется, чтобы не выполнять массовую выгрузку.

Файл `stations-api-worker.js` — небольшой прокси Cloudflare Workers. Он обращается к фиксированному API, добавляет разрешённые CORS-заголовки, передаёт `429` и `Retry-After`, не кэширует ответ и не принимает произвольный URL. Размер области ограничен, чтобы нельзя было выгрузить всю базу.

## Однократная публикация

1. Создайте бесплатный Worker в панели Cloudflare.
2. Откройте редактор кода Worker, замените начальный код содержимым `stations-api-worker.js` и опубликуйте Worker.
3. Проверьте URL Worker: его корневой адрес имеет вид `https://<имя>.<аккаунт>.workers.dev`.
4. В `js/services/stationsApiConfig.js` укажите этот корневой адрес в `FUELWISE_STATIONS_API_URL`, без `/api/stations` и без завершающего `/`.
5. Опубликуйте V3 на GitHub Pages. После обновления приложение будет загружать станции и сведения о топливе через Worker.

Для проверки endpoint используйте адрес вида `https://<имя>.<аккаунт>.workers.dev/api/stations?bbox=55.72,37.58,55.78,37.67`. Ответ должен содержать `stations`, `count` и `truncated`. В браузере приложения статус карты должен сообщить, что данные получены из «Где бензин».

Worker ограничен доменом GitHub Pages проекта и локальным адресом предпросмотра. Если публичный домен приложения изменится, добавьте его origin в `APP_ORIGINS`.

Публичный API может вернуть `429`, старые отметки или пустые цены. Worker не обходит эти ограничения и не делает массовых запросов. Возраст данных по каждой марке топлива приходит от API отдельно.
