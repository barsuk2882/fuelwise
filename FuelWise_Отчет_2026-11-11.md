# Отчёт о работе над FuelWise

**Дата исходного отчёта:** 11 ноября 2026 года
**Актуализация:** 13 ноября 2026 года
**Проект:** FuelWise — планировщик поездок и карта АЗС Города
**Формат:** статическое веб-приложение и PWA на HTML, CSS и JavaScript

> Разделы ниже описывают исходные работы 11–12 ноября. Актуальная визуальная версия и сегодняшние изменения приведены в дополнении в конце отчёта.

## 1. Краткий итог

Работа за день была сосредоточена на публикации проекта, доступе с компьютера и смартфона и исправлении поведения карты АЗС на телефоне.

- Проект опубликован на GitHub Pages: <https://barsuk2882.github.io/fuelwise/>.
- Исходники находятся в публичном репозитории: <https://github.com/barsuk2882/fuelwise>.
- Развёртывание выполняется через GitHub Actions.
- Проверена работа резервной карты АЗС на мобильном скриншоте: карта отобразила 39 станций из сохранённого списка.
- Исправлено чтение резервного списка на мобильных браузерах: теперь он загружается как локальный JavaScript-ресурс, а не только через `fetch` JSON-файла.
- Обновлено сообщение о резервных станциях. Успешное отображение координат больше не оформляется как ошибка; отдельно сохраняется предупреждение, что цены и наличие из резервного набора не актуальны.
- На момент исходного отчёта service worker имел версию `v23`; после удаления редактора демо-заправок версия была `v2-11`. На 12 ноября 2026 года актуальная версия — `v2-15`.

## 2. Исходная ситуация и границы выполненной работы

В папке проекта уже находилось функционирующее приложение FuelWise с расчётами поездок, демо-данными, локальным хранилищем, картой Leaflet и отдельным блоком карты АЗС Москвы. В рамках сегодняшней работы существующий проект был подготовлен к публикации, проверен на GitHub Pages и дополнен исправлениями мобильной загрузки резервных станций.

Исходная работа не заменяла расчётный модуль или демо-маршруты. Основные изменения затронули публикацию, PWA-кэш и сервис карты АЗС. Редактор заправок впоследствии удалён; подробности актуального состояния приведены в разделе 12.

## 4. Карта и загрузка АЗС

### Карта

Карта работает на локальной библиотеке Leaflet. Первым источником подложки для карты маршрута и карты АЗС теперь служит цветная OpenStreetMap; если её тайлы не загружаются, общий модуль `js/mapTiles.js` переключается на контурную MIERUNE. Тайлы карты являются сетевым ресурсом и не помещаются в офлайн-кэш приложения.

### Порядок получения списка и цен

Сервис загружает данные для текущих границ видимой области карты, а не выгружает весь город при каждом запросе.

1. Для той же области карты используется ответ из оперативного кэша страницы, если ему меньше трёх минут.
2. Затем приложение обращается к публичному API «Где бензин» (`https://gde-benzin.ru/api/stations`) с параметром `bbox`. Тайм-аут основного запроса — 4,5 секунды. Если API отвечает, приложение получает список станций и доступные сведения о топливе, включая цены и отметки наличия.
3. Если API цен недоступен, приложение обращается к публичным узлам Overpass OpenStreetMap. Пары узлов проверяются параллельно; тайм-аут каждого запроса — 6 секунд. OpenStreetMap используется для координат и описания объектов. Цены и наличие топлива в этом источнике обычно отсутствуют.
4. Если онлайн-источники не ответили, приложение использует уже полученный ответ из памяти страницы, если он есть.
5. Если такого ответа нет, показываются координаты из резервного снимка: 1470 станций. Снимок датирован 11 ноября 2026 года и не содержит подтверждённых актуальных цен или наличия.

Фильтр топлива применяется к загруженным точкам на устройстве и сам по себе не выполняет сетевой запрос. Кнопка «Обновить» принудительно повторяет запрос, минуя действующий трёхминутный кэш. Повторный запрос не гарантирует свежие цены, если внешний поставщик недоступен.

Автоматического обновления цен по расписанию или в фоновом режиме нет. Серверной части и собственного агрегатора данных у этого статического приложения нет.

## 5. Исправления мобильной версии

### Резервный список станций

На первом мобильном снимке карта подложки открывалась, но список станций не загружался. Интерфейс показывал ошибку чтения резервного JSON-файла (`Failed to fetch`). В проверке из среды разработки опубликованный JSON-файл отвечал успешно, поэтому точную причину поведения конкретного мобильного браузера установить не удалось.

Чтобы резервный сценарий не зависел от отдельного запроса `fetch` за JSON, выполнены изменения:

- создан файл `data/moscow-stations.snapshot.fallback.js` с копией резервного набора;
- файл подключён в `index.html` перед сервисом реальных АЗС;
- `liveFuelStationsService.live.js` сначала использует встроенный набор, а JSON оставляет дополнительным способом чтения;
- новый скрипт добавлен в предварительный кэш service worker;
- версия PWA-кэша увеличена до `v22`, чтобы телефоны получили обновлённые файлы.

После публикации пользователь прислал снимок, где карта показывает 39 станций и карточки. Это подтверждает работу резервного отображения на его телефоне. Онлайн-источники на этом снимке не ответили; поэтому приложение сообщило, что цены и наличие не обновлялись.

### Сообщение о резервных данных

Успешная загрузка резервных точек ранее окрашивалась как ошибка, поскольку резервный ответ имел признак устаревших данных. Это визуально смешивало два состояния: «карта не загрузилась» и «карта загрузилась, но свежие цены недоступны».

Текст статуса изменён: теперь он говорит, что показаны координаты АЗС из резервного списка, онлайн-источники не ответили, цены и наличие не обновлены. Для этого состояния не включается красное оформление ошибки. Настоящие ошибки загрузки по-прежнему показываются отдельно. Версия кэша увеличена до `v23`.

## 8. Текущие ограничения и риски

- Свежие цены зависят от доступности внешнего API и его ответа. Статический фронтенд не управляет этим поставщиком.
- Overpass — резервный источник координат, а не цен и статуса наличия топлива.
- Резервный список координат — снимок, а не автоматически обновляемая база.
- Трёхминутный кэш существует только в памяти открытой страницы; он не является постоянной базой цен.
- Офлайн-кэш включает файлы приложения и резервный список, но не тайлы карты и не актуальные ответы внешних API.
- Для более надёжной регулярной выдачи цен потребуется источник с подтверждённым SLA/API или отдельный серверный адаптер и кэширование. Это отдельное расширение архитектуры; в текущем проекте серверной части нет.

## 12. Актуализация от 12 ноября 2026 года

### Удаление редактора демо-заправок

Из публичного интерфейса удалён блок «Редактор демо-заправок». Удалены его поля формы, стили, обработчики приложения и проверка данных редактора. Сервис заправок больше не накладывает локальные переопределения на демо-список. Демо-данные используются только как локальный справочник типов топлива; карта и рекомендации маршрута используют отдельные сервисы открытых данных.

При запуске `js/storage.js` удаляется устаревший ключ `fuelwise.v2.stationOverrides`. Остальные ключи localStorage, включая параметры автомобиля и историю, сохраняются. Версия Service Worker повышена до `v2-11`, чтобы браузеры получили обновлённые файлы.

Затронуты `index.html`, `css/style.css`, `js/app.js`, `js/ui.js`, `js/validation.js`, `js/storage.js`, `js/services/fuelStationsService.js`, `service-worker.js` и `README.md`. Контекст проекта обновлён в `AI_HANDOFF.md`.

### Проверка приложения во встроенном браузере

12 ноября опубликованная версия открылась по HTTPS во встроенном браузере. Проверены поиск и выбор двух адресных точек, построение автомобильного маршрута, отображение линии и маркеров А/Б, расчёт с ручной ценой и без неё, сообщение при отрицательном расходе, сохранение истории после перезагрузки и восстановление маршрута из истории. Для контрольного маршрута получены 4,7 км и 10 минут; при цене 82 ₽/л расчёт показал 29 ₽. В тестовом профиле браузера остались пять контрольных расчётов.

На карте отобразились тайлы улиц и резервные станции. В видимой области было показано 335 точек; онлайн-источники АЗС в ходе этого прогона не ответили, поэтому цены и наличие топлива не подтверждались.

Проверка `127.0.0.1` из встроенного браузера завершилась тайм-аутом даже при запущенном локальном сервере. Публичная HTTPS-версия при этом открывается и работает. Этот результат отражает недоступность loopback-адреса из встроенного браузера в данной среде; он не доказывает неисправность приложения и не заменяет проверку локального BAT в обычном браузере на компьютере пользователя.

GitHub Pages отдаёт обновлённую версию; в `main` оставлен один корневой коммит с актуальным деревом, как и было согласовано.

### Карты и кэш браузера

Пользователь сообщил, что карты в обычном Chrome оставались пустыми, хотя в другом режиме браузера загружались. Принудительное обновление страницы сочетанием `Ctrl+Shift+R` помогло; это указывает на устаревшие файлы приложения в локальном кэше браузера или Service Worker. Для обновления добавлены явный вызов проверки `registration.update()` и однократная перезагрузка страницы при событии `controllerchange`. Версия PWA-кэша увеличена до `v2-13`, затем до `v2-14` после смены источника тайлов.

По предпочтению пользователя цветная карта OpenStreetMap теперь является основной подложкой и для маршрута, и для заправок. Контурная MIERUNE включается только как резерв, если основной источник не отвечает. Последовательность управляется общим `js/mapTiles.js`. После применения новой версии во встроенном браузере визуально проверена цветная подложка карты маршрута; по дереву страницы подтверждены данные и список точек заправок, карты используют одну схему источников.

Чтобы обычный браузер получил обновлённую версию, открыть [приложение](https://barsuk2882.github.io/fuelwise/) и при необходимости нажать `Ctrl+Shift+R`; на телефоне — закрыть страницу и открыть ссылку снова. Если в будущем цветные тайлы временно недоступны, приложение сохраняет работу карты на контурном резервном источнике. Публичный сервер тайлов не гарантирует непрерывную доступность и должен использоваться с соблюдением [правил OpenStreetMap](https://operations.osmfoundation.org/policies/tiles/).
