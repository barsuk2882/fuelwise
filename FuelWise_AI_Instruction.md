# Исходное ТЗ и актуализация проекта FuelWise

> **Сначала прочитайте эту актуализацию.** Ниже сохранено исходное ТЗ для истории и понимания замысла. Часть его требований уже заменена более поздними решениями. Для работы с текущим приложением руководствуйтесь блоком «Актуальное состояние проекта» в начале файла и исходниками `V3`.

## Актуальное состояние проекта — 13 ноября 2026 года

- Целевая версия — учебный пилот для Москвы, опубликованный как статический сайт и PWA: <https://barsuk2882.github.io/fuelwise/>. Репозиторий: <https://github.com/barsuk2882/fuelwise>.
- Актуальная визуальная версия — V3, направление Route First. Папка `ClaudeProject/V3` содержит отдельную копию проекта и не меняет исходную папку V2.
- Используется HTML, CSS и современный JavaScript без фреймворка и серверной части. Для публикации используется GitHub Pages.
- Маршрут задаётся адресами или названиями объектов в точках А и Б. Пользователь запускает поиск кнопкой и выбирает результат; также доступен выбор координат на карте. Дорожная геометрия, длина и время запрашиваются у публичного сервиса маршрутизации OSRM. При недоступности сервиса приложение не подменяет дорожный маршрут прямой линией.
- Подложка и карта АЗС требуют сети. Обе карты используют общий модуль `js/mapTiles.js`: цветные тайлы OpenStreetMap загружаются первыми, контурная карта MIERUNE служит резервом. При сбое обоих источников приложение показывает сообщение, остальные функции продолжают работать. Публичные серверы тайлов работают без гарантии доступности; загружаются видимые пользователю тайлы, подпись OpenStreetMap показывается на карте, предварительная массовая загрузка не выполняется.
- Адресный поиск использует публичный Nominatim по явному нажатию кнопки. Эти внешние источники являются осознанным последующим решением и заменяют исходное требование о полностью автономном приложении без сетевых API. Секретные ключи в клиентский код не добавлять, HTML сторонних сайтов не парсить.
- Демо-маршруты больше не являются основным сценарием. Пользователь вводит собственные точки. `data/demo-data.json` используется как локальный справочник доступных видов топлива; редактор демо-заправок удалён, потому что он не управлял данными карты и расчётов.
- При запуске `js/storage.js` удаляется только устаревшая запись настроек редактора `fuelwise.v2.stationOverrides`. Параметры автомобиля и история этим не затрагиваются. История хранит до 10 расчётов и позволяет восстановить маршрут по координатам и геометрии.
- PWA-кэш имеет версию `v3-04`. Для дальнейших изменений увеличивайте `CACHE_VERSION` в `service-worker.js`; старые кэши FuelWise удаляются при активации. Если браузер продолжает показывать старую версию, выполните принудительное обновление `Ctrl+Shift+R` на компьютере или закройте и заново откройте страницу на телефоне.
- В V3 карта маршрута — главное полотно; результаты расчёта расположены сразу под ней, карта АЗС и история следуют ниже. Для сравнения с V2 браузерные данные V3 изолированы префиксом `fuelwise.v3`.
- После жалобы на пустые карты принудительное обновление `Ctrl+Shift+R` восстановило их отображение. Это указывало на устаревшие файлы в браузерном/Service Worker-кэше. Для новой версии проверено отображение цветной подложки OpenStreetMap в опубликованном приложении.
- GitHub `main` намеренно хранит один корневой коммит с текущим состоянием, без цепочки прошлых изменений. При публикации эту договорённость нужно сохранять.

Для контрольного маршрута интерфейс показал 4,7 км и 10 минут; при цене 82 ₽/л расчёт показал стоимость 29 ₽. Пять контрольных расчётов остались в локальной истории встроенного браузера.

Во время проверки онлайн-источники АЗС не ответили. Показались резервные станции в видимой области (335 точек), а приложение предупредило, что цены и наличие не обновлены. Это корректная работа резервного сценария, но не подтверждение свежих цен.

После этой проверки приоритет подложки изменён: основной источник — цветной OpenStreetMap, резервный — контурный MIERUNE. Опубликованный сайт после принудительного обновления проверен во встроенном браузере: цветные тайлы карты маршрута загрузились; карта АЗС использует тот же общий модуль тайлов. Последняя версия кэша — `v2-15`. В GitHub `main` хранится один корневой коммит с текущим состоянием; точный SHA доступен в репозитории и не фиксируется здесь, чтобы он не устаревал при обновлении документации.

### Исправление поиска адресов (12 ноября 2026)

Поиск нормализует распространённые сокращения типов улиц (например, «пр-д» → «проезд», «ул.» → «улица») и сначала добавляет к запросу контекст «Москва», если город не указан. Если первый вариант не дал результата, последовательно проверяются дополнительные варианты. Пустые результаты больше не сохраняются в кэш: это позволяет повторить запрос после исправления формулировки или временного сбоя поиска. Кэширование успешных результатов, ограничение частоты запросов и область поиска сохраняются.

Локальный адрес `127.0.0.1` из встроенного браузера недоступен в текущей среде даже при запущенном локальном HTTP-сервере; опубликованная HTTPS-версия открывается. Не путайте ограничение доступа встроенного браузера к loopback-адресу с ошибкой самой веб-страницы.

Создай полноценное, рабочее веб-приложение **FuelWise** — планировщик автомобильных поездок, который помогает водителю снизить затраты на топливо, заранее рассчитать необходимое количество топлива и выбрать заправки по маршруту.

Приложение должно быть полностью автономным: оно работает на локальных демонстрационных данных, без внешних API, без серверной части, без регистрации и без парсинга сторонних сайтов.

Не упоминай в интерфейсе, коде, комментариях, README и названиях переменных какую-либо конкретную страну, регион или валюту. Проект должен быть универсальным и легко адаптируемым под любую страну.

## 1. Тип приложения

Создай **Progressive Web App (PWA)**.

Приложение должно:

- работать в браузере на Android, iPhone, Windows, macOS и Linux;
- корректно отображаться на мобильных устройствах, планшетах и десктопе;
- использовать адаптивный mobile-first интерфейс;
- открываться и работать без сервера;
- поддерживать установку на домашний экран устройства;
- иметь базовую офлайн-поддержку интерфейса;
- хранить пользовательские данные локально в `localStorage`.

Не используй:

- React, Vue, Angular или другие тяжёлые фреймворки, если в этом нет необходимости;
- Node.js, базы данных, серверные языки;
- авторизацию, регистрацию, аккаунты;
- реальные API;
- API-ключи;
- парсинг HTML-страниц сторонних сайтов;
- упоминания конкретных стран или регионов.

Используй HTML5, CSS3 и современный JavaScript. Допускается использование Leaflet для карты.

## 1.1. Ограничения первой версии

В первой версии приложения **запрещено подключать реальные внешние API и внешние источники данных**.

Не подключай и не вызывай:

- реальные сервисы геокодинга;
- реальные сервисы маршрутизации;
- реальные API заправок;
- API карт;
- API цен на топливо;
- API погоды;
- API трафика;
- любые сервисы, требующие API-ключа, токена, регистрации или партнёрского доступа;
- сторонние сайты через парсинг HTML.

Причина: внешние сервисы могут быть недоступны, измениться, потребовать ключей, ограничить количество запросов или нарушить работу приложения. Для первой версии это создаёт лишний риск: проект может не запуститься или перестать работать во время демонстрации.

Вместо этого используй только локальные демонстрационные данные из файла `data/demo-data.json`.

Приложение должно работать полностью офлайн:

- все маршруты берутся из локального файла демо-данных;
- все заправки, цены и наличие топлива берутся из локального файла демо-данных;
- выбор точек А и Б выполняется из заранее подготовленного списка демо-локаций;
- карта и маршрут отображаются на основе локальных координат;
- расчёты выполняются в браузере;
- пользовательские настройки и история хранятся в `localStorage`.

Не оставляй в коде невыполненные функции, пустые обработчики или комментарии вида «реализуй позже». Все основные функции должны быть реализованы и работать на демо-данных.

В будущем пользователь сможет заменить демо-адаптеры на реальные API, но это должно быть отдельным этапом. В первой версии создай только архитектурную возможность для такого расширения: отдельные сервисные файлы с одинаковыми интерфейсами.

Если для какой-то функции нужны внешние данные, которых нет в демо-файле, не подключай внешний сервис. Вместо этого:

- используй заранее подготовленные демо-данные;
- покажи понятное сообщение, что функция работает в демонстрационном режиме;
- предложи пользователю добавить данные вручную, если это уместно.

## 2. Название и назначение

Название приложения: **FuelWise**.

Краткое описание для интерфейса:

> FuelWise помогает спланировать автомобильную поездку: рассчитать расход и стоимость топлива, проверить, хватит ли топлива в баке, найти заправки по маршруту и сравнить варианты поездки.

Основная цель приложения:

> Помочь водителю снизить затраты на топливо за счёт расчёта расхода, выбора заправок, сравнения вариантов маршрута и предупреждения о возможной нехватке топлива.

## 3. Пользовательский сценарий

1. Пользователь открывает приложение.
2. Выбирает точку А и точку Б из списка демо-локаций или указывает их на карте.
3. Вводит параметры автомобиля:
   - расход топлива, л/100 км;
   - текущее количество топлива в баке, л;
   - объём топливного бака, л;
   - тип топлива.
4. Выбирает приоритет поездки:
   - «Дешевле»;
   - «Быстрее»;
   - «Сбалансированно».
5. Нажимает кнопку «Рассчитать поездку».
6. Приложение показывает маршрут, расчёты, заправки и предупреждения.
7. Пользователь может сохранить параметры автомобиля в `localStorage`.
8. Пользователь может посмотреть историю последних расчётов.

## 6. Что должно показывать приложение

После расчёта пользователь должен увидеть:

- карту с маршрутом, точками А и Б, заправками;
- название выбранного маршрута;
- расстояние в километрах;
- ориентировочное время в пути;
- необходимое количество топлива;
- остаток топлива после поездки;
- ориентировочную стоимость топлива;
- список рекомендуемых заправок;
- предупреждение, если топлива не хватит;
- три варианта маршрута;
- сравнение вариантов;
- возможность выбрать вариант и увидеть его на карте.

### Расчёты

Используй следующие формулы:

```text
Необходимое топливо = расстояние / 100 * расход на 100 км
```

```text
Стоимость топлива = необходимое топливо * цена за литр
```

```text
Остаток топлива = топливо в баке + купленное топливо - необходимое топливо
```

Если пользователь должен заправиться в пути, приложение должно учитывать:

- расстояние до первой рекомендуемой заправки;
- цену топлива на этой заправке;
- сколько литров нужно купить;
- дополнительное время на заправку;
- остаток топлива после заправки;
- общую стоимость поездки.

## 7. Логика выбора маршрута

Приложение должно предлагать три варианта:

1. **Самый дешёвый** — минимальная стоимость топлива.
2. **Самый быстрый** — минимальное время в пути.
3. **Сбалансированный** — разумный баланс между ценой и временем.

Для каждого варианта показывай:

- расстояние;
- время в пути;
- необходимое топливо;
- стоимость топлива;
- дополнительные заправки;
- дополнительное время на заправки;
- остаток топлива после поездки.

Используй настраиваемые веса:

```js
const OPTIMIZATION_WEIGHTS = {
  cost: 0.6,
  time: 0.4
};
```

Для сбалансированного варианта используй формулу:

```text
Итоговая оценка =
вес стоимости * нормализованная стоимость
+
вес времени * нормализованное время
```

Чем меньше итоговая оценка, тем лучше вариант.

Все данные должны быть явно демонстрационными. В интерфейсе всегда показывай предупреждение:

> «Расчёт выполнен на демонстрационных данных. Цены и наличие топлива могут не соответствовать реальности».

## 9. Работа с картой

Используй **Leaflet**.

На карте должны быть:

- точка А с маркером;
- точка Б с маркером;
- линия маршрута;
- маркеры заправок;
- возможность приблизить и переместить карту;
- автоматическое масштабирование карты под маршрут;
- всплывающие окна у заправок с названием, ценой и наличием топлива.

Для линии маршрута используй `Polyline`:

```js
const routeLine = L.polyline(routeGeometry, {
  color: "#2563eb",
  weight: 5,
  opacity: 0.8
}).addTo(map);

map.fitBounds(routeLine.getBounds());
```

## 10. Рекомендация заправок

Создай функцию:

```js
getRecommendedStations(route, fuelType, currentFuel, consumption, tankCapacity)
```

Она должна:

1. Найти заправки рядом с маршрутом.
2. Отфильтровать заправки по выбранному типу топлива.
3. Исключить заправки, где нужное топливо недоступно.
4. Рассчитать отклонение от маршрута.
5. Проверить, хватит ли текущего топлива до заправки.
6. Рассчитать, сколько литров нужно купить.
7. Рассчитать дополнительное время на заправку.
8. Отсортировать заправки по цене и удобству.
9. Вернуть не более 3–5 лучших вариантов.

Для каждой заправки показывай:

- название;
- бренд;
- расстояние от маршрута;
- дополнительное время;
- цену топлива;
- наличие топлива;
- сколько литров нужно купить;
- сколько будет стоить заправка.

## 11. Предупреждения

Реализуй следующие предупреждения:

- «Топлива может не хватить до ближайшей заправки».
- «Топлива должно хватить на всю поездку».
- «На маршруте не найдено подходящих заправок с выбранным типом топлива».
- «Не удалось построить маршрут. Выберите другие точки».
- «Введён некорректный расход топлива».
- «Расчёт выполнен на демонстрационных данных».
- «Нет интернет-соединения. Приложение работает с сохранёнными данными».

Используй разные цвета:

- зелёный — топлива достаточно;
- жёлтый — топлива хватает, но запас небольшой;
- красный — топлива может не хватить;
- серый — демонстрационные данные;
- синий — обычная информация.

- точку Б;
- расстояние;
- расход топлива;
- тип топлива;
- ориентировочную стоимость;

Добавь функции:

`localStorage` хранит данные в виде строк, поэтому объекты нужно сохранять через `JSON.stringify()` и читать через `JSON.parse()`.
